Audit the code

The cryptographic core of OSL is published so anyone can verify how encryption works.

What's published here

These are the parts of OSL that matter for verifying the encryption claims — the cryptographic primitives, the message ratchet, the key store, the steganography for cover envelopes, and the threat model. You can read them in your browser or download a zip for offline review. The code in these files compiles inside the full OSL client; it isn't a stand-alone buildable project.

What isn't published

The Discord integration layer, the keyserver, the build pipeline, and parts of the licensing infrastructure are not public. OSL is a small project, and these are the pieces that — if forked — would mostly enable rebranding and reselling the same product rather than meaningful security review.

  • Discord integration — the code that hooks into the Discord client. Reading it tells you almost nothing about message security; it would just make it easier for someone to clone the product.
  • Keyserver — the small Cloudflare Worker that handles license validation and Stripe webhooks. Its job is to say "yes this license is valid" or "no it isn't." It never sees messages.
  • Build and packaging scripts — these have signing keys and deploy credentials baked in.

Why this setup

Open source is a real privacy guarantee for the parts where it matters: the crypto. If the encryption code is wrong, no amount of business-level openness fixes it. Conversely, publishing the full client wouldn't help anyone verify your messages are private — it would just let competitors copy the product. The split is honest: cryptography is auditable; the business is not.

How to verify

Download a release, look at the published crypto code, and confirm the binary corresponds to the code you read. Reproducible builds are planned. If you find something wrong with the cryptography, please contact OSLPrivacy@gmail.com — security reports are welcome and we'd rather hear about it from you than from someone else.
